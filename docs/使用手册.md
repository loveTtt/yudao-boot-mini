# WMS 使用手册

本文档面向开发人员和实施人员，说明如何在当前 WMS / ASRS 项目中新增模块、配置菜单权限、使用代码生成，并完成前后端联调。

相关入口：

- 后端启动模块：`wms-server`
- 后台前端目录：`wms-ui/wms-ui-admin-vue3`
- 菜单管理前端页面：`src/views/system/menu/index.vue`
- 代码生成前端页面：`src/views/infra/codegen/index.vue`
- 菜单管理后端接口：`wms-module-system/.../permission/MenuController.java`
- 代码生成后端接口：`wms-module-infra/.../codegen/CodegenController.java`

## 1. 使用前准备

### 1.1 本地服务

使用菜单和代码生成前，至少需要启动：

- MySQL
- Redis
- 后端服务 `wms-server`
- 前端管理后台 `wms-ui/wms-ui-admin-vue3`

后端启动示例：

```bash
mvn -pl wms-server -am spring-boot:run
```

前端启动示例：

```bash
cd wms-ui/wms-ui-admin-vue3
pnpm install
pnpm dev
```

接口文档入口：

```text
http://localhost:48080/swagger-ui
http://localhost:48080/v3/api-docs
```

前端 API 地址以 `wms-ui/wms-ui-admin-vue3/.env.local` 和 Vite 配置为准。

### 1.2 数据库脚本

当前 MySQL 脚本目录：

```text
sql/mysql/
├─ wms-asrs.sql
└─ quartz.sql
```

菜单、角色菜单关系、代码生成配置相关表在业务脚本中维护：

- `system_menu`
- `system_role_menu`
- `infra_codegen_table`
- `infra_codegen_column`

使用代码生成前，先确认目标业务表已在当前连接的 MySQL 库中创建。

## 2. 菜单与权限模型

### 2.1 菜单类型

后台菜单一般分为三类：

| 类型 | 用途 | 示例 |
| --- | --- | --- |
| 目录 | 菜单分组，不直接对应具体页面 | 系统管理、基础设施 |
| 菜单 | 对应一个前端页面路由 | 用户管理、菜单管理、代码生成 |
| 按钮 | 对应页面内操作权限 | 新增、修改、删除、导出 |

菜单数据存储在 `system_menu`，角色和菜单的授权关系存储在 `system_role_menu`。

### 2.2 权限标识

权限标识建议使用以下格式：

```text
模块:资源:动作
```

示例：

```text
system:user:create
system:user:update
system:user:delete
system:user:query
system:user:export
infra:codegen:query
```

后端接口通过 `@SaCheckPermission` 校验权限：

```java
@SaCheckPermission("system:user:create")
@PostMapping("/create")
@Operation(summary = "创建用户")
public CommonResult<Long> createUser(@Valid @RequestBody UserSaveReqVO reqVO) {
    Long id = userService.createUser(reqVO);
    return success(id);
}
```

后台按钮权限必须和后端注解保持一致。前端隐藏按钮不是安全边界，最终必须以后端权限校验为准。

### 2.3 前端路由来源

当前项目的前端路由由后端菜单树驱动，大致链路为：

```text
AuthController
  -> AuthPermissionInfoRespVO
  -> src/store/modules/user.ts
  -> src/store/modules/permission.ts
  -> 动态路由
```

因此，页面文件存在但菜单未配置时，用户登录后可能看不到入口。

## 3. 在后台新增菜单

### 3.1 新增目录

适用场景：需要增加一个新的一级或二级菜单分组。

操作步骤：

1. 登录后台管理系统。
2. 进入 `系统管理 -> 菜单管理`。
3. 点击新增。
4. 菜单类型选择 `目录`。
5. 填写目录名称、上级菜单、排序、图标等信息。
6. 保存。

目录只负责分组，不需要填写具体前端组件路径。

### 3.2 新增菜单

适用场景：需要增加一个可点击的页面入口。

操作步骤：

1. 进入 `系统管理 -> 菜单管理`。
2. 选择上级目录。
3. 点击新增。
4. 菜单类型选择 `菜单`。
5. 填写菜单名称、路由地址、组件路径、权限标识、排序等信息。
6. 保存。
7. 重新登录或刷新前端权限数据。

菜单配置需要和前端页面文件一致。例如页面文件为：

```text
wms-ui/wms-ui-admin-vue3/src/views/demo/order/index.vue
```

菜单组件路径应按当前前端项目约定填写为类似：

```text
demo/order/index
```

具体格式以现有菜单管理页面和已有菜单数据为准。

### 3.3 新增按钮权限

适用场景：页面已存在，但需要控制新增、修改、删除、导出等操作。

操作步骤：

1. 进入 `系统管理 -> 菜单管理`。
2. 找到目标页面菜单。
3. 点击新增子菜单。
4. 菜单类型选择 `按钮`。
5. 填写按钮名称和权限标识。
6. 保存。
7. 在角色管理中给角色授权。

按钮权限示例：

| 按钮 | 权限标识 |
| --- | --- |
| 查询 | `demo:order:query` |
| 新增 | `demo:order:create` |
| 修改 | `demo:order:update` |
| 删除 | `demo:order:delete` |
| 导出 | `demo:order:export` |

后端接口示例：

```java
@SaCheckPermission("demo:order:delete")
@DeleteMapping("/delete")
@Operation(summary = "删除订单")
public CommonResult<Boolean> deleteOrder(@RequestParam("id") Long id) {
    orderService.deleteOrder(id);
    return success(true);
}
```

### 3.4 给角色授权

菜单或按钮新增后，用户仍可能看不到或不能点击，因为角色尚未授权。

操作步骤：

1. 进入 `系统管理 -> 角色管理`。
2. 找到目标角色。
3. 打开菜单权限配置。
4. 勾选新增的目录、菜单和按钮。
5. 保存。
6. 让用户重新登录，或刷新权限缓存。

## 4. 新增后端模块

### 4.1 模块放置位置

当前后端模块结构：

```text
wms-module-system
wms-module-infra
```

新增业务模块建议新建独立 Maven 模块，例如：

```text
wms-module-wms
wms-module-asrs
```

如果只是系统管理或基础设施能力扩展，应放入已有模块：

| 功能类型 | 推荐模块 |
| --- | --- |
| 用户、角色、部门、权限 | `wms-module-system` |
| 文件、配置、代码生成、API 文档 | `wms-module-infra` |
| WMS 业务功能 | 新建或使用业务模块，例如 `wms-module-wms` |
| ASRS 业务功能 | 新建或使用业务模块，例如 `wms-module-asrs` |

### 4.2 后端分层落点

新增一个资源时，推荐按以下结构落地：

```text
wms-module-xxx
└─ src/main/java/com/jsmauto/wms/module/xxx
   ├─ controller/admin/demo
   │  ├─ DemoController.java
   │  └─ vo
   │     ├─ DemoSaveReqVO.java
   │     ├─ DemoPageReqVO.java
   │     └─ DemoRespVO.java
   ├─ service/demo
   │  ├─ DemoService.java
   │  └─ DemoServiceImpl.java
   ├─ dal/dataobject/demo
   │  └─ DemoDO.java
   ├─ dal/mysql/demo
   │  └─ DemoMapper.java
   └─ convert/demo
      └─ DemoConvert.java
```

Controller 示例：

```java
@Tag(name = "管理后台 - 示例")
@RestController
@RequestMapping("/demo/demo")
@Validated
public class DemoController {

    @Resource
    private DemoService demoService;

    @PostMapping("/create")
    @Operation(summary = "创建示例")
    @SaCheckPermission("demo:demo:create")
    public CommonResult<Long> createDemo(@Valid @RequestBody DemoSaveReqVO reqVO) {
        return success(demoService.createDemo(reqVO));
    }
}
```

Mapper 示例：

```java
@Mapper
public interface DemoMapper extends BaseMapperX<DemoDO> {

    default PageResult<DemoDO> selectPage(DemoPageReqVO reqVO) {
        return selectPage(reqVO, new LambdaQueryWrapperX<DemoDO>()
                .likeIfPresent(DemoDO::getName, reqVO.getName())
                .eqIfPresent(DemoDO::getStatus, reqVO.getStatus())
                .betweenIfPresent(DemoDO::getCreateTime, reqVO.getCreateTime())
                .orderByDesc(DemoDO::getId));
    }
}
```

### 4.3 Maven 聚合关系

新增 Maven 模块后，需要检查：

1. 根 `pom.xml` 是否加入新模块。
2. 新模块是否继承项目父 POM。
3. `wms-server` 是否依赖新模块。
4. 新模块包路径是否在 Spring Boot 扫描范围内。

`wms-server` 只负责启动和聚合，不要把业务代码写进启动模块。

## 5. 代码生成使用流程

代码生成适合标准 CRUD 功能。复杂业务流程可以先生成基础代码，再手工调整 Service、Controller 和前端页面。

### 5.1 创建业务表

先在 MySQL 中创建业务表。示例：

```sql
CREATE TABLE demo_order (
    id          bigint       NOT NULL COMMENT '编号',
    order_no    varchar(64)  NOT NULL COMMENT '订单号',
    status      tinyint      NOT NULL COMMENT '状态',
    tenant_id   bigint       DEFAULT NULL COMMENT '租户编号',
    creator     varchar(64)  DEFAULT '' COMMENT '创建者',
    create_time datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updater     varchar(64)  DEFAULT '' COMMENT '更新者',
    update_time datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    deleted     bit(1)       NOT NULL DEFAULT b'0' COMMENT '是否删除',
    PRIMARY KEY (id),
    UNIQUE KEY uk_demo_order_no (order_no),
    KEY idx_demo_order_tenant_status (tenant_id, status)
) COMMENT = '示例订单';
```

表设计要求：

- 表名带模块前缀。
- 字段必须有注释。
- 主键使用 `id`。
- 多租户数据保留 `tenant_id`。
- 逻辑删除字段使用 `deleted`。
- 查询字段按需要建立索引。

### 5.2 导入表

操作步骤：

1. 登录后台管理系统。
2. 进入 `基础设施 -> 代码生成`。
3. 点击导入。
4. 选择刚创建的业务表。
5. 确认导入。

导入后，系统会把表和字段元数据保存到：

- `infra_codegen_table`
- `infra_codegen_column`

如果列表中看不到表，先检查：

- 后端连接的数据库是否正确。
- 表是否已经创建成功。
- 当前数据库用户是否有读取元数据权限。
- 表是否已经导入过。

### 5.3 编辑生成配置

导入表后，进入编辑配置页面，重点检查：

| 配置 | 说明 |
| --- | --- |
| 基础包名 | 应保持在 `com.jsmauto.wms` 下 |
| 模块名 | 例如 `demo`、`wms`、`asrs` |
| 业务名 | 例如 `order` |
| 类名称 | 例如 `DemoOrder` |
| 类描述 | 用于生成接口文档和页面标题 |
| 作者 | 按团队约定填写 |
| 生成模板 | 按当前项目支持的模板选择 |
| 前端路径 | 应匹配 `wms-ui/wms-ui-admin-vue3/src/views` 下的目标路径 |

字段配置重点检查：

- 哪些字段进入列表。
- 哪些字段进入查询条件。
- 哪些字段进入新增和修改表单。
- 字段控件类型是否正确。
- 字典字段是否选择了正确字典。
- 必填字段是否和数据库约束一致。

### 5.4 预览代码

生成前先预览代码，重点检查：

- Controller 路径是否符合模块规范。
- 权限标识是否符合 `模块:资源:动作`。
- DO 的 `@TableName` 是否正确。
- Mapper 是否继承 `BaseMapperX`。
- 查询条件是否合理。
- 前端页面路径是否和菜单组件路径一致。
- SQL 菜单数据是否符合预期。

不要不看预览就直接合并生成结果。

### 5.5 下载或生成代码

根据项目代码生成页面支持的能力，选择下载代码或直接生成。

合并代码时按以下顺序处理：

1. 后端 Controller、VO、Service、Mapper、DO、Convert。
2. 前端 API 文件。
3. 前端页面文件。
4. SQL 菜单和权限数据。
5. 角色授权。
6. 本地启动验证。

如果生成结果覆盖已有文件，必须先看 diff，再决定是否覆盖。

## 6. 代码生成后的检查清单

### 6.1 后端检查

- [ ] DO 的 `@TableName` 是否等于真实表名。
- [ ] DO 是否继承正确基类，例如多租户表继承 `TenantBaseDO`。
- [ ] Mapper 是否继承 `BaseMapperX<DO>`。
- [ ] 分页查询是否返回 `PageResult<DO>`。
- [ ] Controller 是否返回 `CommonResult<T>`。
- [ ] Controller 是否使用 `@Tag`、`@Operation`。
- [ ] 管理后台接口是否配置 `@SaCheckPermission`。
- [ ] 权限标识是否和菜单按钮一致。
- [ ] Service 是否处理必要业务校验。
- [ ] 写操作是否需要事务。

### 6.2 前端检查

- [ ] 页面是否生成到 `src/views` 下正确目录。
- [ ] API 文件路径是否符合当前项目约定。
- [ ] 页面组件路径是否和菜单配置一致。
- [ ] 查询、新增、修改、删除按钮是否绑定对应权限。
- [ ] 字典、枚举、状态展示是否正确。
- [ ] 列表分页是否正常。

### 6.3 菜单权限检查

- [ ] 是否生成或手动新增目录。
- [ ] 是否生成或手动新增菜单。
- [ ] 是否生成或手动新增按钮权限。
- [ ] 是否给目标角色授权。
- [ ] 用户是否重新登录或刷新权限。

## 8. 常见问题

### 8.1 菜单不显示

排查顺序：

1. 菜单是否已保存到 `system_menu`。
2. 菜单状态是否启用。
3. 父级目录是否启用。
4. 当前角色是否已勾选该菜单。
5. 用户是否重新登录。
6. 前端组件路径是否正确。

### 8.2 页面 404 或空白

常见原因：

- 菜单组件路径和 `src/views` 下实际文件路径不一致。
- 前端文件未生成或未合并。
- 前端开发服务未重启。
- 路由缓存未刷新。

处理方式：

1. 检查页面文件是否存在。
2. 对照已有菜单的组件路径格式。
3. 重新登录后台。
4. 必要时重启前端服务。

### 8.3 接口返回 403

常见原因：

- 后端 `@SaCheckPermission` 权限标识和菜单按钮权限不一致。
- 当前角色没有授权按钮权限。
- 用户登录态仍是旧权限。

处理方式：

1. 检查 Controller 上的权限字符串。
2. 检查菜单管理中的按钮权限字符串。
3. 检查角色授权。
4. 重新登录。

### 8.4 代码生成看不到表

排查顺序：

1. 表是否创建在后端当前连接的数据库。
2. `application-local.yaml` 的数据源是否指向目标库。
3. 数据库用户是否有表元数据读取权限。
4. 表是否已经导入过。
5. 表名是否符合项目命名规范。

### 8.5 生成代码后编译失败

常见原因：

- 包名、模块名配置错误。
- 生成代码落到错误模块。
- Maven 模块没有被根工程聚合。
- `wms-server` 没有依赖新增模块。
- 字典、枚举、类型转换缺失。

处理方式：

1. 先看编译错误的第一个文件。
2. 检查 package 路径是否和目录一致。
3. 检查模块 POM 和根 POM。
4. 检查 `wms-server` 依赖。
5. 再处理字段类型和转换问题。

### 8.6 修改权限后仍不生效

常见原因：

- 用户未重新登录。
- 权限数据被缓存。
- 角色授权未保存。
- 菜单状态未启用。

处理方式：

1. 退出并重新登录。
2. 确认角色菜单关系已保存。
3. 检查菜单状态。
4. 如仍异常，再检查 Redis 中权限相关缓存。
